# 10 - Dashboard and automated tests

The programme had results but neither an interface nor an automated check. This
document describes the two additions foreseen in [SPEC.md](../SPEC.md).

## 1. Dashboard

**Address**: https://lorenzo-bianchi-lab.github.io/euro-stablecoin-exposure/

It is a single HTML page (`docs/index.html`), generated by `src/dashboard.py` and published
by GitHub Pages as it is. It has no server and loads nothing from outside: data and
calculations are inside the page, which also works when opened from a file.

| Element | What it does |
|---|---|
| Amount slider | Dollar stablecoins held in the euro area, from 0 to USD 700 billion |
| Preset levels | Own minimum; today with a share of 7.5% and 15%; ESM baseline 2030, high 2030, high with a 15% share |
| Share funded with deposits | Substitution rate, from 0 to 100% |
| Allocation across countries | R1 in proportion to sight deposits; R2 per capita; R3 by crypto-asset owners |
| From outflow to credit | Threshold, uniform, low coefficient, high coefficient |
| Summary boxes | Deposits to be replaced, sight deposits lost, extra wholesale funding, credit reduction |
| Country table | Sortable; outflow, deposits lost, effect on funding, wholesale funding, credit reduction |
| Two-channel map | The 21 countries by sight deposits and dollar liabilities, with the quadrants and the scenario values on mouse-over |
| Weekly index | EUR share for USDT or USDC, with and without Coinbase, and the flag status |

The calculations in the browser use the same formulas as modules 4 and 5. An automated
test runs the page's code and compares it with the results of the scripts.

Construction choices:

- No external library: charts drawn in SVG by the page's code.
- Colours checked for legibility, including for colour blindness, in light and dark theme.
- Every chart shows its values on mouse-over; the table gives the same numbers in
  text form.
- The programme's caveats are in the page, not in a separate document.

## 2. Automated tests

```bash
.venv/bin/python -m unittest discover -s tests -v
```

| Test | What it checks |
|---|---|
| Balance-sheet reconciliation | In all country-month observations the liability items sum to the total within 0.5% |
| Coverage | The last month contains all 21 countries |
| Linearity of scenarios | Doubling the amount doubles the outflow, the effect on funding and the wholesale funding need, for each rule |
| Sum of allocations | For each rule across countries and across deposit types, the outflows by country sum to the amount |
| File consistency | In the scenario files the totals by country match the declared amount |
| Property of R1 | With the proportional rule all countries lose the same percentage of sight deposits |
| Credit | Low coefficient never above the high one; uniform rule equal to half the outflow; linearity |
| Dashboard | The page's code, run outside the browser, reproduces the outflow, wholesale funding need and credit of the scripts |
| Reproducibility without network | Re-running the whole programme in a copy, without network, produces identical result files |

**Outcome on 2026-11-25**: 9 tests out of 9 passed, in about 7 seconds, after a complete
run of `run_all.py` with download from the sources. Rule R3 is included in the
linearity, sum and dashboard tests.

The reproducibility test found a defect on its first run: module 1 rounded
circulation only when saving it, so the results computed with and without network
differed at the sixth decimal place. It now rounds before computing.

## 3. Updating

The single command also regenerates the summary and the dashboard:

```bash
.venv/bin/python src/run_all.py
```

GitHub Pages republishes the page at each push of `docs/index.html`.

## 4. Limitations

- The dashboard shows a snapshot: the data are those of the last run of
  `run_all.py`, they do not update by themselves.
- The tests check the internal consistency of the programme, not the correctness of the
  sources or the validity of the assumptions.
- The dashboard test requires `node`; if it is missing the test is skipped and says so.
- The reproducibility test covers the main result files, not the charts.

---

**What this adds to the final programme**: an interface that an analyst can use
without installing anything, to try any amount, rule and substitution rate; and a set
of tests showing that the numbers on the page are the same as those of the scripts and
that the programme is reproducible.
